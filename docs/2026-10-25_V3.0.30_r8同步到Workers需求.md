### 1-3. 後端已提供的雲端文件寫入功能（2026-10-25 發現）

後端窗口（作者 Adem）於 2026-10-25 17:04 推了分支 `feat/sync-starter-and-cloud-watchlist`，KuPei 審查後已合併進 `kupei-pages` 的 `main`（`ab4cbf9`）。它換成後端新版 starter，並加入自選與雲端同步。以下是 KuPei 從 starter 程式碼讀到的 API（**尚未以寫入權杖實測**，定義請後端在 W-16 確認）：

| 端點 | 說明 |
| --- | --- |
| `GET /api/store` | 列出所有文件的 `key`、`version`、`updatedAt`、`bytes`（不含內容） |
| `GET /api/store/<key>` | 取得文件；沒有時 `version` 0、`data` null |
| `PUT /api/store/<key>` | 整包寫入，本文 `{ baseVersion, data }`；`baseVersion` 必須等於目前雲端版本（第一次為 0），不符回 **409**，`details` 是雲端最新文件 |
| `DELETE /api/store/<key>?baseVersion=<版本>` | 刪除；版本不符 409、不存在 404 |

- 驗證：標頭 `Authorization: Bearer <寫入權杖>`；寫入權杖是唯讀權杖的超集，設定後客戶端所有請求都改用它。
- 公開站用法：文件 key 為 `watchlist`，內容 `{ "ids": ["3529", …] }`；使用者在頁面的「雲端同步」貼上寫入權杖，權杖只存在那台裝置的瀏覽器（`localStorage` 的 `kupei:write-token`），**不在原始碼、不是 GitHub secret**。沒有權杖時自選只存在本機。
- 與 KuPei 私人主機的自選（SQLite）**是兩套獨立資料**，不互通。
- 本文件的同步範圍仍只有評分資料；雲端文件不在同步範圍，但 CORS、權杖與備份需要一併確認（W-16）。
