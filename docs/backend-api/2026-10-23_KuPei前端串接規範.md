# KuPei 前端串接規範（後端窗口 → KuPei）

日期：2026-10-23　發文：後端窗口　收件：CoKu／KuPei 專案
性質：**串接契約。** 回覆《2026-10-23_KuPei部署資訊需求清單》，並明訂 KuPei 前端串接後端的唯一方式。
基準文件：`KuPei-API.md`、`openapi.json`（與本文件同資料夾）。本文件與 `KuPei-API.md` 衝突時，以 `KuPei-API.md` 為準。

## 0. 一句話

後端窗口提供的是**一個已上線、可讀可存的 API 服務**，不是一台主機。KuPei 前端**必須**依 `KuPei-API.md` 的端點與格式串接：評分與行情用唯讀權杖讀，前端改的任何資料用寫入權杖整包存到雲端文件（`/api/store`），跨裝置同步。後端的實作方式、部署位置、維運由後端窗口負責，不對外說明、不開放存取；對 KuPei 而言，契約就是全部的介面。

## 2. 串接規則（必須遵守）

1. **只能使用 `KuPei-API.md` 列出的端點。** 未列出的路徑一律視為不存在，不得探測、不得依賴。
2. 每個請求帶 `Authorization: Bearer <權杖>`。權杖從環境變數讀取，**不得**寫進原始碼、版控、文件或 AI 對話。
3. 先讀 `/data/manifest.json` 取得 `run`，再讀 `/data/<run>/…`。**不得**寫死批次編號。
4. `/api/*` 每個 IP 每分鐘 30 次，超過回 429；**不得**輪詢。`/data/*` 不限次數，`summary.json` 讀一次後留在記憶體。
5. 開發階段前端跑在 `localhost`／`127.0.0.1`，不需設定。正式站**由 KuPei 部署到 GitHub Pages**（流程見《KuPei-前端部署指南-GitHub-Pages.md》），部署前**必須**把來源 `https://<帳號>.github.io` 告知後端窗口加入白名單，否則瀏覽器會擋。權杖只透過 GitHub Actions secret 注入建置。
6. 排序、底色、漲跌幅、股價格式依 `KuPei-API.md` 附錄 B，不自行發明規則。
7. 回應欄位**只增不減**。KuPei 前端須容忍新增欄位；後端若需移除或改變既有欄位，會以新版本路徑提供並事先書面預告。
8. 錯誤處理依 `KuPei-API.md`「錯誤」節：401 檢查權杖、403 不繞過、429 依 `Retry-After` 等待、409 載入最新內容重做。
9. **寫入一律走 `/api/store`，用寫入權杖。** 寫入權杖**不得**進建置、環境變數、GitHub secret 或原始碼；由使用者在 App 設定畫面輸入一次、存於該裝置。每個資料類型一個 key、整包存、帶 `baseVersion`。
10. **批次檔請求必須帶版本參數** `?v=<manifest.hashes 對應值>`（details 用 `published_at`），讓瀏覽器長期快取；`manifest.json` 不得快取。直接用 `starter/kupei-client.ts` 即符合；自行實作者依 `KuPei-API.md`「快取與載入」。

## 3. 不在本契約範圍內（後端不提供）

- 使用者帳號系統（身分就是兩把權杖：唯讀給網頁、寫入給使用者本人）
- 盤中即時行情、SSE 推送（只有每日收盤）
- 估價、新聞、個股報告的**計算與產生**；報告排程的**執行**（排程設定可以存在 `/api/store`，但後端不會跑）
- Tailscale、SSH、任何主機層級存取
- 站長本人的自選（`/api/watchlist`）與手動補抓——與 KuPei 無關的內部端點

KuPei 若需要以上功能，只有兩種做法：
- **(a)** 在前端本機處理，不經後端（例如即時行情前端自行接 FinMind）。
- **(b)** 以書面提出變更需求，由後端窗口評估範圍與時程後另行約定。

**不得**在未約定的情況下假設後端會提供，也不得把 KuPei 既有 FastAPI 的端點（`/api/v1/*`）當成本服務的一部分。

### 3.1 建議的前端自理方式（做法 (a) 的具體建議）

| 原本在 KuPei FastAPI | 前端怎麼做 | 代價 |
| --- | --- | --- |
| 自選群組、個人設定、個股問題 | **雲端文件 `/api/store`**（各一個 key，`store.update()` 讀改寫），本機 `localStorage` 當快取 | 需使用者輸入一次寫入權杖；跨裝置自動同步 |
| 即時行情 SSE（每 30 秒） | 前端直接呼叫 FinMind（KuPei 自己的 token），30 秒輪詢 | token 在瀏覽器裡；FinMind 的 CORS 與額度由 KuPei 自行確認 |
| 安全邊際用即時價計算 | 原設計即在前端 | 無 |
| 估價 | 由批次交付 `valuation.json`（KuPei 端算好），後端原樣發布、不計算；前端只顯示（`loadValuation()`，`null` 就不顯示）。`vparams.json` 只是參數說明表 | 2026-10-27 更新：原寫「公式在前端算」已不適用 |
| 排序、篩選、搜尋、分數樹、原因碼翻譯 | 前端，規則依 `KuPei-API.md` 附錄 B | 無 |
| 月營收 | 讀後端 `/api/market/history`，或前端接 FinMind | 無 |
| 報告排程 | 設定存 `/api/store`；**執行**不提供 | 要真的產報告走做法 (b) |
| 個股 AI 報告、新聞 | 暫不做（金鑰不可放前端） | 之後若需要，走做法 (b) |

## 4. 評分資料更新

- 資料流向：**KuPei 管線產出批次 → 交付後端窗口 → 後端窗口發布 → `manifest.json` 的 `run` 更新。** 前端自動讀到新批次，不需改程式。
- 目前線上批次：`local_full_20261014_171209`（1,976 家，`spec_version` V0.0.26）。
- 要讓 V3.0.29（1,979 家）上線，KuPei 須**主動交付**批次檔。格式須與目前 `summary.json`、`details/*.json`、`nodes.json`、`tr.json`、`vparams.json` 相同（型別見 `KuPei-API.md` 附錄 A）；若格式不同，先交付一份樣本，由後端窗口評估轉接方式與時程。
- 交付管道與頻率雙方另約。後端窗口**不連 KuPei 的主機、不主動拉資料**。
- 批次一旦發布，該 `run` 資料夾內容不再變動；更正以新 `run` 發布。

## 5. 驗收（KuPei 前端完成時由雙方一起跑）

1. `GET /api/health` → 200
2. 帶權杖 `GET /data/manifest.json` → 200；不帶權杖 → 401
3. 帶權杖 `GET /api/market/latest` → 200，畫面顯示的收盤日與回應的 `dates` 一致
4. 帶權杖 `GET /api/watchlist` → 403（確認前端沒有誤用超出範圍的端點）
5. 開啟前端瀏覽器的 Network 面板走一輪主流程：沒有任何對未列出端點的請求、沒有 429；批次檔請求帶 `?v=`，**重新整理後批次檔來自快取（memory／disk cache），只有 `manifest.json` 和 `/api/*` 走網路**
6. 原始碼與版控中搜不到任何權杖字串（唯讀、寫入都不行）
7. 兩台裝置（或兩個瀏覽器）輸入寫入權杖後改自選，互相重新整理看得到；在 A 用舊版本寫入會收到 409 並載入最新內容，不會覆蓋 B 的修改

## 6. 變更管理

- 本文件與 `KuPei-API.md` 由後端窗口維護；任何修改以書面（含日期）通知 KuPei。
- KuPei 的需求變更一律以書面提出，後端窗口回覆可否與時程；**未回覆前視為不提供**。
- 本契約不設期限；任一方要終止，書面通知後，後端窗口作廢權杖即生效。
