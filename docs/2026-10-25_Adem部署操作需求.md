# Adem 部署操作需求

使用者已決定取消私人主機，請以現有雲端服務承接正式功能。這是待執行需求；不代表現有部署已完成全部功能。

## 請先回覆

| 項目 | 需要內容 | 回覆 |
| --- | --- | --- |
| 原始碼 | 後端程式的儲存庫／本機資料夾位置，或原始碼封裝的安全交付方式 | 待回覆 |
| 分工 | 是否由 Codex 修改後端程式、Adem 操作雲端部署；前端由 Claude 維護 | 待回覆 |
| 測試環境 | 能否先建立與正式環境隔離的測試部署 | 待回覆 |
| 平台資源 | 所需持久化儲存、檔案儲存、排程與串流服務是否可使用；方案額度與費用由誰確認 | 待回覆 |
| 私有交付 | 資料包與完整技術需求的安全接收方式 | 待回覆 |
| 時程 | 各階段可開始、可測試與預計完成時間 | 待回覆 |

不要在此文件、commit 或對話中填寫密碼、權杖、私鑰或 API key。完整契約、資料清單及驗證資訊由使用者另行提供私有交付包，不提交公開 repo。

## 請依序操作

1. 提供後端原始碼與既有部署設定的安全交付方式，確認操作權限及分工。
2. 建立測試環境，保留現有服務與使用者資料，確認失敗時可回復。
3. 依私有需求文件配置身分驗證、持久化儲存及私有檔案儲存；區分公開展示與個人資料權限。
4. 接收正式資料包，依包內清單逐檔驗證；新批次驗證完成後再切換，保留舊批次。
5. 補齊完整自選、設定與問題管理；驗證跨裝置同步及同時修改衝突處理。
6. 補齊即時行情、歷史資料、估價與排程；具體時間與資料契約依私有文件執行。
7. 補齊新聞、報告工作流與參考資料上傳；保留必要的人工審核。
8. 設定備份匯出、異常紀錄與還原流程，完成隔離還原演練。
9. 與完整正式前端整合，完成桌機／手機、權限、排程、檔案與回退驗收後，再由使用者核准正式啟用。

現有展示前端並未涵蓋全部正式功能；請不要只更新展示資料就標示整體完成。Codex 負責後端與資料契約，Claude 負責前端與畫面複查，Adem 的實際部署操作範圍請先於上表確認。

## 每階段回覆格式

- 已完成內容與對應程式版本。
- 測試環境與測試結果（不得附帶憑證）。
- 尚缺資料、平台資源或其他阻塞。
- 下一階段完成時間及回復方式。

私人資料包只透過雙方約定的安全管道傳送；公開 repo 僅存本操作需求文件。原始碼與測試環境尚未確認前，不能承諾全功能部署完成日期。
